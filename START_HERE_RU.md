# ITERATION_001 — локальная сборка, запуск и сбор логов

Это исходный проект с патчем ENTRY_FIX и оболочкой для проверки на вашем Windows-ноутбуке.
Новых изменений геометрии, тарифов, nearest-правила и алгоритмов в этой итерации нет.
Готовый JAR/Docker image здесь не прилагается: их собирает и проверяет ваш Docker.

## Запуск

1. Распакуйте архив **в новую папку**, не поверх прежней рабочей копии. Например, `C:\heatnet\iter001`.
2. Запустите Docker Desktop в режиме Linux containers и дождитесь готовности движка.
3. Закройте ненужные приложения. Последовательно используются контейнеры Maven с лимитом 4 ГБ,
   приложения с лимитом 8 ГБ (Java heap 6 ГБ) и проверки с лимитом 2 ГБ. Это ограничения, не измеренные пики.
4. Дважды нажмите **RUN_AND_COLLECT.cmd**. Локально Java/Maven/Python устанавливать не нужно.
5. Дождитесь надписи **SEND THIS FILE** и пришлите указанный `ITERATION_001_LOGS_*.zip`.
   При ошибке сборки также присылайте этот архив — не нужно вручную исправлять код или пропускать тесты.

Первый запуск требует интернета для загрузки образов, Maven- и Python-зависимостей.
Нельзя обещать конкретное время загрузки. После подготовки образов расчёт не вызывает внешние API.
Политика PowerShell меняется только для запуска данного процесса, системные настройки не меняются.

Сервис этой итерации слушает **http://localhost:18080/viewer/**, а не прежний порт 8080.
Публикация ограничена 127.0.0.1. Другие Docker-проекты не останавливаются.
Если 18080 занят, из PowerShell в папке проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\local_iteration\run.ps1 -Port 18081
```

Остановить именно этот стенд: **STOP_ITERATION.cmd**. Тома Docker и старые результаты не удаляются.
Повторный запуск останавливает только предыдущий `heatnet_iter001` и пересоздаёт приложение.
Не запускайте два RUN_AND_COLLECT одновременно. Последовательная проверка нужна, чтобы не смешивать budgets.

## Что произойдёт

- Проверка доступности Docker и Compose.
- `mvn clean package` (включая тесты) внутри Maven/Java 11 контейнера; ошибки не обходятся через skipTests.
- Python-тесты исправленного checker-а и исходный smoke-набор.
- Упаковка **полученного после тестов JAR** в образ приложения и запуск.
- Чтение `/api/trace/configuration` и `/algorithms`.
- Три одиночные диагностики 2/5/10 (сохранены все препятствия и существующая сеть), по 20 с внутреннего бюджета.
- Два последовательных запуска неизменного исходного GeoJSON: B3 и FIRST-FULL, по 120 с внутреннего бюджета.
- Независимая проверка каждого успешного GeoJSON в `DOCUMENT_NEAREST_V1`.
- Архив результатов и ошибок. Частичный ответ явно остаётся PARTIAL; 17/17 не предполагаются заранее.

HTTP ожидание включает дополнительное время сверх бюджета solver-а; это не обещание его соблюдения Java-кодом.
После транспортной ошибки batch останавливается, чтобы следующий запрос не конкурировал с ещё выполняющимся.

## Что находится в возвращаемом ZIP

Логи Maven/сборки образов/сервера, surefire-отчёты, настройки API, хеш JAR, release manifest,
Python-зависимости, параметры запросов, HTTP-заголовки, исходные тестовые GeoJSON,
result.geojson, checker-report.json и сводка qa-live.json. При раннем отказе доступны только выполненные стадии.

Ничего автоматически не отправляется. Архив создаётся даже при штатно пойманной ошибке.
При закрытии окна или выключении ПК архив может не создаться: файлы остаются в `iteration_logs/`.
Перед отправкой просмотрите логи: исключения могут содержать локальные пути и содержимое тестовых данных.
Не добавляйте `.env`, Docker credentials, токены или дамп всех переменных окружения.

## Граница выполненной проверки

Автор проверяет отдельные функции Python-runner-а и структуру комплекта. Полная Windows/PowerShell,
Maven/Spring/Docker-интеграция в среде автора не выполнена. Её результат получим из первого архива логов.
Именно для этого подготовлена итерация; пакет не объявляется заранее успешно собранным приложением.

Следующий выпуск будет иметь новый iteration id и отдельную папку. Не смешивайте файлы разных итераций.
Если меняете код локально, приложите patch или архив изменённых файлов вместе с логами.
