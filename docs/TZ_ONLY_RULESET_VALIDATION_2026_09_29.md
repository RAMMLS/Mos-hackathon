# Проверка алгоритма только по ТЗ

Дата: 29.09.2026.

## Вывод по правилу входа в ОКС

В техническом приложении, раздел 2.2, и в разъяснениях, вопрос 3, установлено одно
правило: для содержащего целевую точку полигона ОКС разрешается один финальный прямой
участок через ближайшую к точке границу. Отступ от собственного полигона на этот участок
не распространяется. Остальные ограничения сохраняются.

Следовательно, `EXPERIMENTAL_ANY_BOUNDARY_V1` не является профилем сдачи. Для API,
viewer, benchmark и финального GeoJSON применяется `DOCUMENT_NEAREST_V1`, hash
`9d11fd5c124dee727569e4cb7f0aba9926d1c8d764f1c0c27a91075fa5b4ee32`.

## Что было исправлено

Строгий профиль сначала подключал 13 из 17 ОКС. Для ОКС 3 был построен корректный
конечный подход, но основной поиск не использовал уже существующий visibility graph.
После его включения обнаружился второй дефект: предварительный маршрут выбирал ДУ 125,
а фактический обход длиной около 560 м требовал ДУ 150. После инженерного пересчета
геометрия не перепроверялась под выросший габарит.

Реализовано:

- visibility graph используется только после неудачи обычного A*;
- вершины обхода строятся по диаметрозависимому габариту ограничения;
- после итогового расчета расхода, длины и ДУ перепрокладывается любой участок, чей
  новый габарит не проходит проверку;
- добавлен интеграционный тест одиночного ОКС 3 в `DOCUMENT_NEAREST_V1`.

Одиночный ОКС 3 после исправления: `FULL 1/1`, внешний checker `VALID`, нарушений 0.

## Неподключенные точки

После исправления неподключены `2`, `5`, `10`.

- ОКС 2, полигон 77: фиксированный луч через ближайшую границу повторно входит в тот
  же полигон до появления коридора полного требуемого отступа.
- ОКС 10, полигон 88: аналогичная ситуация на вогнутой геометрии.
- ОКС 5, полигон 72: ближайшая математическая граница является внутренним кольцом
  полигона. ТЗ не уточняет, считать ли внутреннее кольцо допустимой границей входа или
  использовать только внешний контур. Текущий checker требует ближайшую границу, но
  одновременно требует единственное пересечение внешнего контура, поэтому этот случай
  требует явного решения о трактовке.

Нельзя честно объявлять 17/17 по ТЗ, пока эта неоднозначность не разрешена либо не найден
маршрут, проходящий текущий строгий checker.

Production defaults соответствуют ТЗ, B3 и PORTFOLIO возвращают сертифицированную
частичную сеть 14/17. Для полной сдачи приоритетом является официальный вопрос по
внутренним кольцам полигона и формализация ожидаемого поведения для геометрически
зажатого ближайшего входа. До этого экспериментальный результат 17/17 не используется
как доказательство соответствия ТЗ.
