# R1 PPO v1: реализованный ограниченный контур

Дата: 2026-09-19.

## Что сделано

Реализован исполняемый обучаемый контур R1 как отдельный Java-класс `R1Solver`:

- конечный каталог конкретных действий и стабильные `action_id`;
- сохранение `candidate_ids`, признаков и маски внутри PPO-rollout;
- маскирование недопустимых и уже выполненных действий;
- награда `(best_before - best_after) / initial_score`;
- лучший архив не ухудшается при плохом или неуспешном действии;
- NumPy actor/critic и clipped PPO update;
- versioned model manifest и hash весов;
- Java inference режимов `R1` и совместимого alias `R1-PILOT`;
- независимая проверка финального GeoJSON.

R1 v1 использует действия `BUILD_BACKBONE(B2-U/Q/C/B2-C-J)`, `DESTROY_REPAIR(B3)` и `STOP`. Это полный
исполняемый цикл для объявленного конечного каталога: observation, mask, PPO inference, транзакционная оценка,
best archive, reward accounting и экспорт. Он не равен более широкому R1 v2 из исследовательского предложения,
где действия должны редактировать отдельные объекты текущего графа.

## Данные пилота

Train содержит четыре сцены из официального parent-датасета (3, 5, 8 и 12 ОКС) и отдельную выгодную
junction-сцену. Validation содержит три независимых parent-источника: smoke-сцену, отрицательную junction-сцену
и исследовательскую сцену «Коммунарка».
Каждый B1/B2/B3 witness построен Java solver-ом и проверен независимым checker-ом. Невалидные или неполные
варианты маскируются.

Это достаточный набор для sanity-check контура, но недостаточный для оценки обобщения. В спецификации целевой
порядок величины — 1000/200/300 независимых parent-сцен для train/validation/test.

## Результат обучения

Модель: `models/r1_pilot_v1/model.json`.

- epochs: 750;
- seed: 101;
- train oracle matches: 5/5;
- validation oracle matches: 3/3;
- model weights hash: `cd55b131e68ceede9cceb93235ab3b3a168313d1a0425214068f122d58d6251e`;
- train 3 ОКС: сохраняет B1, score 5.06;
- train 5 ОКС: сохраняет B1, score 7.06;
- train 8 ОКС: выбирает B2-U, `8.44 -> 6.34`;
- train 12 ОКС: находит B3, `11.67 -> 8.12`;
- validation 2 ОКС: все варианты равны 2.33, ухудшения нет;
- validation «Коммунарка»: находит B3, `5.72 -> 5.16`, подключено 4/4 ОКС.

Это подтверждает полный контур на независимой сцене с ненулевым улучшением, но три validation-сцены все еще
слишком малы для статистического вывода об обобщении.

## Java end-to-end

На полном обновленном датасете `R1-PILOT`:

- выбрал `B2-C -> B3 -> B2-C-J -> B2-U -> B2-Q -> STOP`;
- подключил 17/17 ОКС;
- длина 1504.95 м;
- стоимость 228 974 801.11 руб.;
- score 10.93;
- нарушений checker-а: 0;
- время end-to-end: 30.55 с.

Python и Java выбрали одинаковую последовательность при одинаковом наблюдении и весах. Проверка сравнивает
вектор состояния, сырые logits, последовательность действий и hash весов. Она также нашла и помогла исправить
реальный дефект: Java первоначально строила стартовый B1 в другом routing-контексте, чем данные обучения.

## Тесты

Команда:

```bash
python -m unittest scripts.r1.test_core -v
```

Проходят 13 тестов: стабильный rollout, неизменность candidate snapshot при PPO update, stale snapshot,
маскированные действия, rollback, телескопическая награда, дорогой законный ход, нулевая вероятность незаконного
хода, schema/hash model guard, перестановка каталога, split leakage, обязательная coverage и конечный горизонт.

Полная parity-проверка:

```bash
python -m scripts.r1.check_java_parity
```

## Граница реализованного R1 v1

`R1-PILOT` пока выбирает готовые полные шаблоны. До полного R1 не хватает:

1. `CONNECT`, `ATTACH`, `MERGE` и `REATTACH` с конкретными ID объектов; `JUNCTION_IN_EDGE` уже реализован в
   детерминированном действии `B2-C-J`;
2. применения одного локального изменения к текущему проекту вместо переключения целого шаблона;
3. графового encoder-а узлов и ребер;
4. сотен независимых training/validation/test parent-сцен;
5. сравнения с B3 при одинаковом wall-clock и одинаковом seed archive;
6. расширения raw-logit parity с одного полного прогона до набора сохраненных наблюдений.

API `R1` теперь исполняет этот обученный контур и имеет статус `IMPLEMENTED_EXPERIMENTAL`; `R1-PILOT` оставлен
для воспроизводимости прежних команд. Production-готовность не заявляется до реализации перечисленных локальных
действий и статистической проверки на существенно большем отложенном наборе.
