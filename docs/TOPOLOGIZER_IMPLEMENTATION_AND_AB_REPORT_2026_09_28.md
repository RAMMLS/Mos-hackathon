# Отчет по сертификации и топологизации сети

Дата: 2026-09-28

## Итог

Приоритеты P0-P3 реализованы в рабочем контуре и проверены неизменным
многосценовым бенчмарком. Главный измеренный результат для `B3`, `R2` и
`PORTFOLIO`: валидность выросла с 13/16 до 15/16, а среднее покрытие ОКС - с
54,49% до 60,28%.

Лучший основной алгоритм по этому прогону - `B3`: его качество совпало с `R2`
и `PORTFOLIO`, но среднее время меньше. Для внешнего API оставлен
`PORTFOLIO`, поскольку он выбирает лучший сертифицированный результат из
нескольких независимых ветвей.

Работа не объявляется завершенной на 100%: одна tie-in stress сцена из 16 пока
не имеет ни одного сертифицированного решения. Текущий топологизатор надежно
собирает совпадающие и сходящиеся хвосты, а также заменяет циклообразующие
параллельные ветви врезкой в общий ствол. Полный noding всех произвольных
пересечений сети пока не выполняется.

### Сертификация API

- Обычный `/api/trace` возвращает только результат, прошедший внутреннюю и
  постэкспортную проверку.
- Если подходящего решения нет, API отвечает `422 NO_CERTIFIED_SOLUTION` и
  указывает источник отказа.
- Диагностический вариант доступен только по явному
  `diagnosticFallback=true`.
- Заголовок `X-Solution-Certified` позволяет отличить проектный ответ от
  диагностики без разбора GeoJSON.
- `/api/trace/configuration` публикует режим сертификации и значение fallback
  по умолчанию.

### Топологизация и пересчет

В генерацию дерева добавлена нормализация общих хвостов:

1. распознаются одинаковые линии независимо от служебных ID;
2. поддерживается совпадение геометрии в обратном направлении;
3. близкие сходящиеся последние участки заменяются двумя подходами к одной
   развилке и общим стволом;
4. если две ветви идут рядом, расходятся и снова сходятся, одна ветвь безопасно
   врезается в другую до начала параллельного участка вместо создания цикла;
5. перед принятием проверяются циклы, единственность родителя и допустимые
   угловые переходы;
6. после изменения дерева расход агрегируется от потребителей, затем заново
   выбираются диаметры, камеры и стоимость;
7. полученная геометрия повторно сертифицируется после округления координат,
   используемого GeoJSON writer-ом.

### Безопасная дедупликация

Fingerprint конструкции нужен только для статистики разнообразия и удаления
точных повторов поиска. Квантование уменьшено с 0,1 м до 0,001 м, поэтому две
полезные трассы с разницей 2 см больше не схлопываются. Любая конструкция все
равно проходит полный геометрический сертификатор.

алгоритмом, несмотря на улучшение его среднего score.

## Проверки и тесты

- P0: fallback не возвращается неявно; явный fallback имеет диагностическую
  маркировку.
- Экспорт: координаты проходят round-trip с точностью GeoJSON без потери
  расхода и стоимости.
- Дедупликация: обратное направление считается той же конструкцией, а сдвиг
  2 см - другой.
- Цикл: любое объединение с циклическими parent links отклоняется до агрегации
  расхода.
- Угол, степень камеры, пересечения ОКС, наложения и диаметры проверяются
  внутренним сертификатором и независимым benchmark checker-ом.
- `mvn test` и полный Docker benchmark выполняются отдельно; результаты
  бенчмарка содержат GeoJSON и checker-report для каждого принятого ответа.
- Точечный checker новой операции:
  `results/api-certification-smoke-2026-09-28/parallel-repair-checker.json` -
  `VALID 4/6`, ноль нарушений.

## Что остается до полного общего топологизатора

Для закрытия последней tie-in stress сцены и поддержки неизвестных комбинаций
нужен отдельный графовый проход над всей сетью:

1. выполнить noding в пересечениях и на границах каждого частичного
   совпадения;
2. разбить маршруты на атомарные ребра и сохранить provenance
   `ОКС -> исходный маршрут -> атомарные ребра`;
3. объединить одинаковые ребра независимо от общего родителя исходных трасс;
4. выбрать ориентацию к допустимым точкам врезки без циклов и потери
   потребителей;
5. пересчитать поток, диаметр, камеры, стоимость и габариты;
6. проверить идемпотентность: повторная нормализация не меняет сеть;
7. прогнать тот же A/B, меняя только проход сборки сети.

Именно это остается следующим инженерным шагом. Текущий результат уже доказал,
что объединение физически общего ствола дает заметный прирост: добавлены две
валидные сцены из 16 без регрессии ранее валидных результатов B3. Полный
произвольный graph-noding пока не реализован и в отчете не выдается за готовый.
