# Контракт результата GeoJSON

Источник: пользовательское «Техническое приложение.docx», §10. Таблицы сохранены из ранее подготовленной спецификации.

## Приложение B. Обязательные поля выходных сущностей

Источник: ТА, §10.1–10.7. Технические имена и типы перенесены из исходных таблиц. Поля находятся в `properties`; `geometry` и `type = "Feature"` находятся на уровне GeoJSON-feature. Общие поля намеренно повторены для каждого типа, чтобы реализацию можно было сверять построчно.


### B.1. `heat_network`

| Поле | Тип | Значение / описание из ТА |
| --- | --- | --- |
| `id` | string | Уникальный идентификатор участка |
| `object_type` | string | heat_network |
| `variant_id` | string | ID варианта |
| `start_node_id` | string | ID точки врезки, тепловой камеры, технического узла или точки подключения ОКС |
| `end_node_id` | string | ID объекта, соответствующего второму концу участка |
| `flow_tph` | number | Расход участка, т/ч |
| `diameter` | integer | Условный диаметр, мм |
| `length` | number | Длина участка, м |
| `laying_method` | string | Обычная прокладка (base) или специальный проход (special) |
| `depth_start` | number / null | Глубина до верха расчётного габарита, м; для основной двумерной задачи – null |
| `depth_end` | number / null | Глубина до верха расчётного габарита, м; для основной двумерной задачи – null |
| `cost` | number | Стоимость участка, руб. |
