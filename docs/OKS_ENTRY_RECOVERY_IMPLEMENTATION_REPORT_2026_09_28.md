## Почему стало 14 вместо 15

Предыдущая контрольная точка `15/17` использовала фиксированный отступ `0,75 м` внутри RoutePlanner и не проверяла полный диаметрозависимый горизонтальный отступ в Python checker-е. Техническое приложение требует для ОКС минимум `5/7/9 м` в зависимости от ДУ, а для оси трубы также учитывается половина ширины пары.

Интервальный анализ обнаружил третью цель того же класса:

- ОКС `10`, собственный полигон `88`;
- первый свободный интервал ближайшего луча: `6,989 м`;
- верхняя граница достижимого отступа на нём: `3,495 м`;
- требуемый отступ оси при ДУ 125: `5,300 м`.

Следовательно, прежний portal ОКС `10` не соответствует полному отступу. Сохранить старые 15 ID можно только вернув неполную модель правила, поэтому такая подгонка не сделана.

## Реализованные изменения

### ENTRY-01 Профили правил

Ruleset и стратегия поиска остаются разными параметрами. Для каждого профиля API теперь возвращает:

- стабильный ID;
- SHA-256 канонического определения;
- источник правила;
- признак `experimental`;
- текст определения.

Для `DOCUMENT_NEAREST_V1`:

```text
9d11fd5c124dee727569e4cb7f0aba9926d1c8d764f1c0c27a91075fa5b4ee32
```

Ответ `/api/trace` содержит `X-Ruleset-Id`, `X-Ruleset-Hash` и `X-Ruleset-Experimental`. Python checker записывает тот же hash в отчёт.

### ENTRY-02 Интервальный анализ

Новый `EntryApproachPlanner`:

1. находит ближайшую точку полной границы собственного полигона;
2. строит фиксированный прямой луч от точки ОКС;
3. пересекает луч с материалом Polygon/MultiPolygon;
4. выделяет первый выход и первое повторное вхождение;
5. вычисляет длину свободного интервала и строгую верхнюю границу `gap / 2`;
6. сравнивает её с нормативным отступом плюс половиной ширины пары;
7. сохраняет witness с ограничением области доказательства.

Для ОКС `2`:

```text
gap=3,680 м
clearance_upper_bound=1,840 м
required=5,255-5,300 м
```

Для ОКС `5`:

```text
gap=4,137 м
clearance_upper_bound=2,069 м
required=5,300-5,325 м
```

Причина имеет область действия `fixed_nearest_boundary_straight_ray`; она не называется доказательством глобальной невозможности подключения.

### ENTRY-03 Кэш подходов

Ключ кэша включает:

- координату endpoint с миллиметровым квантованием;
- требуемый ДУ;
- ruleset;
- entry strategy.

На одиночном ОКС `2` выполнено два уникальных анализа для двух реально запрошенных ДУ и получен 31 cache hit. На ОКС `5` также выполнено два анализа и получено 30 cache hits. При смене ДУ создаётся новая запись.

## Ограничения текущей сертификации

Python checker подтверждает связность, расходы, диаметры, повороты, запрещённые пересечения, специальные пересечения и стоимость. Он ещё не проверяет все горизонтальные отступы с учётом ДУ и ширины пары. Поэтому `VALID 14/17` означает прохождение текущего checker-а, а не полную внешнюю сертификацию ТЗ.

До добавления диаметрозависимых отступов в общий RoutePlanner и checker нельзя честно сравнивать стоимость нового результата с историческим `15/17` или `17/17` как варианты одной и той же задачи.
