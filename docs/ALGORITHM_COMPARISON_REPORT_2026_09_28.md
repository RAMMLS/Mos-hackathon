## 4. Что показал каждый алгоритм

| Алгоритм | Сильная сторона | Конкретный недостаток в этом прогоне |
|---|---|---|
| B0-GRID | Очень быстрый контрольный baseline | Не подключил ОКС 5 и 6; независимые маршруты не используют выгоду общей сети |
| B0-CORRIDOR | Быстрый baseline с коридорной геометрией | На этой сцене полностью повторил B0-GRID и также подключил только 4/6 |
| B1 | Regret-вставка использует уже построенную сеть | Не нашел допустимый маршрут для ОКС 2 и 3; полный результат не получен |
| B2-U | Простой и быстрый общий backbone | Выбор medoid не учитывает расход или цену; на иных сценах может выбрать слабый корень |
| B2-Q | Лучшее время среди полных победителей; medoid учитывает расход | На этой сцене не лучше B2-U по качеству, преимущество только по измеренному времени |
| B2-C | Medoid учитывает строительную стоимость | Получил тот же вариант, что U/Q; ценовое взвешивание здесь не дало дополнительного улучшения |
| B2-C-J | Явно ищет выгодные присоединения к ребрам | После общей нормализации трассы не улучшил B2-C, хотя выполнил дополнительный поиск |
| B3 | Перебирает destroy/repair и хранит сертифицированный архив | Рассмотрел 750 допустимых кандидатов, но вернулся к B2-U; примерно в 9 раз медленнее B2-Q |
| R1-PILOT | RL выбирает последовательность готовых решателей | Итог совпал с эвристикой; пилот управляет крупными действиями, а не строит геометрию самостоятельно |

| X0 | Перебрал все 720 порядков подключения для 6 ОКС | Ограничен малыми сценами; не улучшил быстрый B2-Q |
| X1 | Точный поиск родительского дерева как oracle | В 56 раз медленнее B2-Q и не дал выигрыша на этой сцене |
| X2 | Добавляет ограниченный Steiner graph DP | Самый тяжелый одиночный алгоритм; дополнительных точек Штейнера с выигрышем не найдено |
| PORTFOLIO | Параллельно запускает B2-C-J, B3, R1, R2, X1 и X2 и сертифицирует результат | На простой сцене платит временем за надежность; выбран B2-C-J, но score совпал с быстрыми B2 |

## 5. Вывод

Для этой сцены лучший практический одиночный алгоритм — `B2-Q`: он дал минимальный score 3,23, подключил 6/6 ОКС и завершился за 0,072 с.

Для демонстрационного и production API следует оставить `PORTFOLIO`. Причина не в том, что он улучшил эту конкретную сцену, а в том, что он параллельно проверяет несколько классов поиска, отбрасывает несертифицированные варианты и возвращает лучший допустимый. На текущем прогоне он выбрал `B2-C-J`; все шесть ветвей портфеля завершились без ошибок.

Главный отрицательный результат прогона: RL и точные X1/X2 пока не превзошли качественную эвристику B2 на этой сцене. Следующая цель улучшения — не еще один локальный вариант той же топологии, а сцены, где B2 попадает в иной локальный минимум: несколько источников, неодинаковые расходы, сложные препятствия и конкурирующие общие стволы.
