Дата: 2026-09-27

## Краткий вывод

Production-кандидатом остаётся `PORTFOLIO`. После доработок он хранит проверенные
решения B3, R2 и R1 в общем архиве, не теряет B2/B2-C-J seeds внутри B3 и для малых
сцен продолжает улучшение через X1/X2.

Финальный единый benchmark после всех правок выполнен на контрольных 112 хешах:
6 алгоритмов, 672 запуска, 672/672 VALID и 100% подключение ОКС. PORTFOLIO имеет
лучший общий mean score 3.992 и 112 побед с учётом ничьих. На независимом test split
20/20 PORTFOLIO и X2 имеют mean score 4.034 и выигрывают все 20 сцен; PORTFOLIO
остаётся production-кандидатом, потому что дополнительно хранит проверенные B3/R1/R2
incumbent-ы и не зависит от успешности одной ветки.

Это не означает, что все исследовательские расширения master plan T01-T15 уже
реализованы. Инженерный контур доверия и полный benchmark завершены; topology repair,
chamber relocation и learned selector остаются отдельными исследовательскими этапами.

## Что реализовано

1. Воспроизводимый `run-manifest.json`: SHA-256 входов, правил, checker-а, Java solver-а,
   моделей, build-файлов и реализации route cache; Git commit/dirty state и параметры
   запуска объединяются в стабильный `configuration_id`.
2. `CertifiedArchive`: принимает только допустимые конечные решения, хранит снимки,
   сравнивает полноту подключения раньше score и не позволяет поздней мутации испортить
   incumbent.
3. B3 архивирует реальные B2-U/B2-Q/B2-C/B2-C-J решения, strict B1 fallback и все
   прошедшие geometry guard destroy/repair-кандидаты.
4. R2 сохраняет incumbent при исключении отдельного оператора.
5. R1 начинает episode с лучшего из 13 concrete seeds, а не только `flow_desc`.
6. Route cache v2 разделяет запросы по координатам, режиму, требуемому ДУ и роли участка.
   В результат добавляются hit/miss/unique counters.
7. Добавлен bounded regional repair для групп 2-4 ОКС. Он честно помечен как
   `model_kind=bounded_order_surrogate`, ограничен 48 кандидатами и всегда сохраняет
   incumbent.
8. PORTFOLIO сравнивает B3, R2 и R1 через общий архив; X1/X2 получают лучший seed.
9. Runner различает `TIMEOUT/DEADLINE_EXCEEDED`, `NETWORK_ERROR`, `IO_ERROR`, HTTP-отказ
   и `CHECKER_REJECTED`.
10. Закреплён regression pack трёх прежних B2-C-J INVALID-сцен.
11. API принимает необязательный `budgetMs`; R1/R2/B3/PORTFOLIO проверяют общий
    монотонный дедлайн между кандидатами и возвращают последний certified incumbent.
    Benchmark runner автоматически оставляет Java пять секунд до сетевого timeout.
12. Дедлайн протянут внутрь visibility graph и A*: тяжёлый геометрический поиск
    кооперативно прекращается, не уничтожая уже найденный incumbent.
13. Standalone R1/R2 применяют тот же geometry guard, что PORTFOLIO; пять старых
    INVALID R1 и два INVALID R2 закреплены повторным прогоном 10/10 VALID.
14. Multi-scene runner умеет точно выбирать 112 `selected_for_rl` сцен, фильтровать
    конкретные scene id и выполнять детерминированный параллельный прогон.

## Регрессии

- Java: 6/6 тестов PASS (`CertifiedArchive`, route-cache isolation, R2 failure/deadline fallback).
- Deadline smoke: при `budgetMs=1` PORTFOLIO вернул B3 за 50 мс; checker дал
  VALID, 6/6 ОКС, score 6.47, `deadline_reached=true`.
- Checker smoke: 10/10 PASS, включая hairpin, диаметр, спецпересечение, запретную зону.
- Junction regression: PASS; полезная развилка 0.91 -> 0.80, неполезная сохраняет 0.79.
- Старые B2-C-J INVALID: 3/3 сцены теперь VALID для B2-C, B2-C-J, B2-U и B3.
- B3 не хуже лучшего валидного B2-U/B2-C-J seed на закреплённых сценах.
- Финальный benchmark: 672/672 VALID, 112/112 полных подключений у каждого алгоритма.
- Тяжёлая timeout-сцена: R2, X2, PORTFOLIO вернули VALID 6/6 примерно за 115 с,
  `deadline_reached=true`, до внешнего timeout 120 с.

## Следующий инженерный шаг

Не следует объявлять T01-T15 полностью закрытыми. Следующий приоритет:

1. Профиль 1644-scene stress-пула для одного production-профиля PORTFOLIO.
2. Полноценный local topology repair с boundary context и oracle для 2-4 ОКС.
3. Chamber relocation/collapse и проверяемый chain shortcut.
4. После этого controlled retraining selector-а на новых действиях и независимом split.
