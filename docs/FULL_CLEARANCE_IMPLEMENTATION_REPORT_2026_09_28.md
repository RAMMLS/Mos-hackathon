## Что изменено

### Java solver

- Добавлен декларативный каталог `ClearanceRules` с ширинами пары труб и нормами по типам ограничений.
- Для ОКС применяется `5/7/9 м + W(ДУ)/2`.
- Для дорог и трамвая применяется `1,5 м + W(ДУ)/2`.
- Для газопровода и кабеля учитываются обе расчётные полуширины.
- Для обычного прохода проверяется минимальное расстояние по всей линии, а не только её вершины.
- Фактический ДУ передаётся через direct, dogleg, A*, shortcut и итоговую геометрическую проверку.
- Исключение собственного ОКС применяется только к проверенному конечному прямому участку.
- Версия route-cache повышена до `route-cache-v6-full-clearance`, чтобы старые решения не переиспользовались.

### Независимый checker

- Версия повышена до `benchmark_checker_v0.3-full-horizontal-clearance`.
- Добавлены непрерывные расстояния segment-to-segment.
- Проверяются полигоны ОКС, park, social_area, prohibited_site, water, railway.
- Проверяются road, tram_tracks, gas_pipeline, power_cable и существующая heat_network.
- Для каждого нарушения сохраняются ID сегмента и ограничения, ДУ, фактический и требуемый зазор.
- Спецпересечение и конечный вход рассматриваются локально; они не удаляют препятствие из всей карты.
- Численная политика: нарушение фиксируется, если дефицит превышает `0,01 м`. Поэтому минимальный сырой margin новой базы `-0,003 м` принят как пограничный случай внутри допуска.

## Что осталось до полного результата

1. ОКС 2, 5 и 10 остаются локально заблокированными фиксированным лучом к абсолютно ближайшей границе. Для альтернативной грани требуется явный отдельный ruleset либо ответ организаторов.
2. ОКС 3 достижим старой геометрией, но эта геометрия нарушала полный габарит. Нужен новый локальный reroute или перестройка соседних развилок.
3. B0/B1/B2 должны хранить лучший строгий частичный incumbent, иначе API отвечает `NO_CERTIFIED_SOLUTION`, хотя часть ОКС могла быть подключена.
4. R1/R2 пока не создают новую топологию: на этом входе они воспроизводят B3. Переобучение имеет смысл после добавления действий локального reroute и смены схемы объединения.
5. Следующая цель оптимизатора: сначала вернуть ОКС 3 без нарушения габарита, затем отдельно исследовать 2/5/10 в экспериментальном профиле границы. Все сравнения вести через checker v0.3 или новее.

## Честный статус

Алгоритм теперь работает корректнее и проверяемее, но задача не завершена на 100%: строгая сертифицированная база покрывает 13 из 17 ОКС. Улучшать дальше нужно сам поиск допустимой топологии, а не ослаблять нормы или checker.
