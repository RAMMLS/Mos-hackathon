## Краткая суть задачи

Нужно сделать backend-сервис, который принимает один GeoJSON FeatureCollection в EPSG:4326, строит варианты подключения перспективных ОКС к существующей тепловой сети, рассчитывает расходы, диаметры, камеры, врезки, спецпроходы, реконструкцию существующей сети, стоимость и ранжирование вариантов. Все метрические операции выполняются после преобразования в EPSG:32637.

Финальный результат также должен быть GeoJSON FeatureCollection, где варианты различаются `variant_id`. В выходе ожидаются новые участки сети, точки врезки, реконструируемые части существующей сети, новые и реконструируемые камеры, технические узлы и `variant_summary`.

## Как бы я решал

1. Сначала реализовать детерминированный расчетный контур: загрузка GeoJSON, валидация, проекция в EPSG:32637, spatial index, граф существующей сети и единый `VariantEvaluator`.
2. Для MVP не начинать с ML. Сделать генератор кандидатов врезки, маршрутизатор допустимых путей и ранжирование через точную функцию из ТЗ.
3. Построить baseline: для каждой точки подключения найти несколько ближайших кандидатов врезки, построить допустимые независимые маршруты, посчитать диаметр, длину, стоимость, реконструкцию и score.
4. Добавить объединение близких ОКС: пробовать общие ветки, камеры ветвления и оставлять объединения только при улучшении score.
5. Затем добавить ограниченный поиск по вариантам: beam search или best-first search с действиями `ChangeTieIn`, `MergeBranches`, `SplitCluster`, `MoveJunction`, `DropOKS`.
6. Отдельно тестировать evaluator: выбор диаметра, предельную длину одного диаметра, стоимость спецпроходов, камеры, врезки, реконструкцию по `upstream_object_id`, штрафы за неподключение.
7. Дополнительную задачу по глубине делать после стабильной 2D-версии: глубина как параметр сегмента, профиль изменения глубины, вертикальные просветы и коэффициент стоимости.

## Архитектура MVP

- Java 11, Spring Boot 2.6.3, docker-compose.
- PostgreSQL/PostGIS или PostgreSQL + in-memory JTS STRtree для первого прототипа.
- Jackson Streaming для больших GeoJSON.
- JTS для геометрии, GeoTools/Proj4J для CRS, JGraphT для графовых операций.
- API в стиле job pipeline: загрузка, запуск расчета, статус, результат, ошибки.

Главный принцип: routing/search только генерирует кандидатов, а окончательное качество варианта определяет один тестируемый `VariantEvaluator`.
